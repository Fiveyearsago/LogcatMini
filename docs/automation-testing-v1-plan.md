# Logcat Mini 自动化测试第一版方案

状态：Mac 实验版的完整设计，保留供后续迭代。本轮实际能力和限制见 [实验版使用说明](automation-testing-mac-preview.md)。日期：2026-10-13。

第一版面向开发自测与 QA 回归：选择 APK、设备和已有测试用例，在本机完成安装、界面操作、结果验证和证据保存，同时提供应用内结果与 Markdown 报告。优先建立可重复运行的测试流程；DeepSeek 用例生成和失败分析留到后续版本。

已确认的客户端范围：第一版先做 Mac，Windows 后续接入；Android 是被测平台。用例和报告格式为后续 Windows 接入保留兼容设计，首版交付与验收聚焦 Mac。本文不要求修改任何目标 App；无法从界面或日志观测的结果应明确标为未覆盖。

## 1 产品目标与范围

第一版验收目标是：开发或 QA 配置过某个应用的核心用例后，可以换入该应用的新 APK，重复运行同一套用例，并从失败项直接找到操作步骤、截图和对应日志。

“通过”仅表示本次所选用例在所记录环境中满足了检查条件。安装成功、日志里没有 Error、界面看起来正常，均不能替代需求验收标准。

| 能力 | 第一版范围 |
| --- | --- |
| APK 输入 | 单个可独立安装的 APK；识别包名、版本、最低系统要求、ABI 与 SHA-256 |
| 设备 | 已授权 ADB 连接的 Android 真机或已有模拟器；一次任务固定一台设备 |
| 任务并发 | 整个客户端同时运行一个自动测试任务，暂不提供排队与多设备并发 |
| 安装 | 未安装时安装；已安装时尝试保留数据覆盖；失败后给出具体原因 |
| 用例 | 按应用管理用例集；可视化编辑、排序、复制、导入和导出 |
| 执行 | 有界的点击、输入、滑动、返回、启动、重启、等待和结果检查 |
| 检查 | 元素可见或不可见、文本、前台应用、限定窗口内的日志出现或不出现 |
| 异常 | 收集目标应用的崩溃、ANR 线索与执行错误；明确采集范围及缺口 |
| 证据 | 步骤记录、应用日志、相关系统事件、关键截图；录屏可选 |
| 结果 | 实时任务状态、最终用例与步骤结果、运行历史、手动重跑失败项 |
| 导出 | Markdown 加证据文件夹；界面与报告读取同一份结果数据 |
| AI | 首版不调用模型、不要求 API Key；预留后续分析扩展 |

首版暂不包含：AAB 或 Split APK 安装、多设备矩阵、iOS、云设备、自动遍历所有页面、录像生成用例、图像像素比对、后台接口断言、性能基准、验证码识别、无人值守处理登录验证、任意脚本执行、定时任务及 CI 集成。

目标 App 的后端网络仍由其测试环境决定。“本机执行”不表示被测 App 不联网。

## 2 使用流程

首次使用某个 App 时，开发或 QA 建立应用配置，写入测试环境说明和前置条件，配置 5 至 10 条核心用例，并在设备上试跑。已有登录账号、权限状态、远程开关等需要纳入前置条件。

后续回归时，选择新 APK，沿用用例集，确认设备和数据策略，运行后查看失败项。用例发生变化时创建新修订，历史运行保留原用例快照。

需求描述作为用例的背景材料保存。首版不会仅凭需求文字自动生成可执行测试，也不会把任意 APK 自动变成完整验收用例。

## 3 界面结构

### 3.1 模块入口

在主窗口增加“日志”和“自动测试”两个入口。日志页沿用现有布局；自动测试页使用自己的导航与内容区。切换页面不会停止正在运行的任务或清空日志。

自动测试左侧依次为“测试任务”“用例库”“运行记录”，底部为设置入口。当前运行任务以固定条显示设备名称、包名和“查看运行”按钮。主题、字体、列表选中态沿用现有应用风格；关键信息使用常驻文字，不依赖悬浮提示。

普通日志采集与测试采集独立。测试期间可以查看其他设备的日志，但测试目标不会随普通日志页的设备选择变化。自动测试占用设备期间，本客户端阻止对同一设备启动另一个测试或手动录屏；其他工具和手机上的人工操作无法完全阻止，需要在运行页标明避免干预。

所有页面中的应用名称、版本、结果数字和设备名称均为布局示意。

拖入文件后异步读取信息，展示解析中、解析失败或解析完成状态。开始按钮旁直接显示阻塞原因，例如“请选择已授权设备”“用例中存在未配置步骤”“执行组件未就绪”。保存草稿不安装 APK、不操作设备。

“开始测试”执行当前表单明确显示的安装与数据策略，不重复询问同一操作。选择“清除应用数据”时，在表单内说明将清除登录状态和本地数据，并要求显式勾选；默认不选择。签名不匹配、版本降级或安装冲突时停止任务，不自动卸载旧 App。

| 配置项 | 默认值与行为 |
| --- | --- |
| 任务名称 | 应用名加版本加日期，可修改 |
| APK | 必选；开始前冻结文件快照并计算校验值，实际安装该快照 |
| 设备 | 可带入当前选择，但必须显示名称和序列号；运行时冻结 |
| 环境 | 应用配置中的环境名称；这是记录标签，不能自动切换 APK 的服务端环境 |
| 环境验证 | 可配置可见的环境标识或日志检查；未配置时报告写“由操作者指定，未自动验证” |
| 用例选择 | 勾选并显示顺序；没有可执行断言的用例不能作为正式验收用例运行 |
| 安装策略 | 安装或保留数据覆盖；首版不提供自动降级、卸载重装 |
| 数据策略 | 保留数据；可显式选择“任务开始前清除一次” |
| 用例隔离 | 每例默认重启 App、保留数据；需要清数据的用例必须显式声明并在开始前汇总 |
| 失败策略 | 停止当前用例；其他独立用例重新准备后继续。公共环境故障停止整次任务 |
| 自动重试 | 关闭；元素查找允许超时内轮询，点击、提交和整个用例不自动重放 |
| 日志与截图 | 必开；失败时截图，明确的截图步骤和检查点保存截图 |
| 录屏 | 默认关闭；打开后按用例录制，超过现有 180 秒能力时标明覆盖范围 |
| 结果目录 | 首次选择后记住；与普通截图、录屏保存目录分开 |

### 3.3 用例库与编辑页

用例库按应用筛选，支持名称、编号和标签搜索，显示优先级、最近修改时间、当前修订、最近一次运行结果。最近结果同时显示 APK 和环境，不能只显示一个没有上下文的绿色勾。

编辑页由“基本信息、前置条件、测试步骤、收尾步骤”组成，详细字段见[配置说明](automation-testing-case-guide.md)。

~~~text
用例库 / 示例应用 / 设置保存后重启仍生效             [复制] [保存]
编号 SETTINGS-001    优先级 P1    标签 设置 / 回归
关联需求：语言设置在重新启动后保留
前置条件：已进入首页；当前语言为中文；测试账号已登录

步骤  操作             目标或输入                   超时    预期
1     点击             id=settings_button           10 s
2     点击             文本=语言                    10 s
3     点击             文本=English                 10 s
4     检查元素可见     id=language_value, 文本=English 10 s    English
5     重启应用                                       30 s
6     点击             id=settings_button           10 s
7     检查元素可见     id=language_value, 文本=English 10 s    English
8     截图             settings-after-restart

[添加步骤] [读取当前页面控件] [检查配置] [试跑本用例]
~~~

“读取当前页面控件”仅在用户操作时读取当前设备的控件树，列表展示可用 ID、文字和描述；选择后填入目标字段，不触发点击。“试跑”同样创建正式运行记录，必须显示设备、应用和数据策略，不能绕过前置校验。

编辑中存在缺失目标、重复步骤编号、无效变量、非法正则或不支持的动作时，定位到具体字段。运行中修改用例只影响新修订，不改变本次快照。

第一版不做持续远程控制画面。此区域显示最近一次保存的截图及时间，避免静态图片被误认为直播。设备动作由执行引擎发出。

优先显示已确认的用例完成数与耗时。只有执行适配器确实收到步骤开始或结束事件，才展示相应步骤状态；无法得到实时步骤事件时，显示“执行界面步骤”，段落结束后补齐结果，不用动画模拟成功。

“停止测试”立即停止发出新动作，终止本任务拥有的执行进程，保留证据并生成部分报告。首版不提供暂停后续跑，避免等待期间应用和服务端状态变化造成误判。停止不能撤销已经发生的提交、安装或数据清除。

结果页提供“全部、失败、阻塞、未完成”筛选；成功项也能展开步骤及证据。错误等级日志作为线索单列，不直接等于用例失败。

历史页支持按应用、版本、设备、环境、结果和时间搜索。可以重新打开旧记录、导出报告、按原配置创建新任务。重跑失败项生成新的 runId，并保存来源 runId，不覆盖原失败记录；若原 APK 快照已不存在，必须重新选择并核对 SHA-256。

历史记录删除需展示要删除的记录及证据目录。自动保留策略首版关闭，不在后台静默删除结果。

### 3.6 设置

设置中增加“自动测试”页：结果保存目录、执行组件路径与版本、Java 路径、默认超时、截图与录屏选项、日志脱敏规则、存储占用。普通日志页的截图目录与字体快捷键继续按现有行为工作。

依赖诊断显示每个组件的可用状态、版本和修复入口。首版采用“检查已安装组件并提供配置说明”，暂不静默下载安装组件。AI 设置不在首版显示为可用功能。

## 4 执行流程

### 4.1 阶段与中间产物

| 阶段 | 执行内容 | 失败后的处理 |
| --- | --- | --- |
| 校验配置 | 校验用例、变量、设备、输出目录、磁盘空间、引擎与 Java 版本 | 不安装；保存失败原因；所选用例标为阻塞 |
| 冻结任务 | 创建 runId，保存 APK 快照、SHA-256、用例与设置快照 | 无法可靠保存时不操作设备 |
| 准备设备 | 固定序列号，检查在线、授权、系统要求、解锁与目标用户配置 | 阻塞；不自动改用另一台设备 |
| 安装 APK | 运行有超时的安装；保存标准输出、错误输出和退出码 | 任务阻塞；不自动卸载或降级 |
| 验证安装 | 核对包名、versionCode、实际安装版本与 UID | 不一致时停止；不可仅靠安装命令退出码通过 |
| 初始化数据 | 按已选择策略清数据，准备可验证的前置条件 | 对应条件不满足记阻塞 |
| 启动采集 | 创建独立日志会话，校准时间，准备异常监测和录屏 | 必需采集不可用则阻塞 |
| 按例执行 | 准备、执行步骤、断言、保存证据、执行有界收尾 | 当前例停止；按故障范围决定能否继续 |
| 完成收集 | 停止本任务进程、结束录屏、保存日志尾部、确认设备状态 | 标明证据缺口；不丢弃已有结果 |
| 生成结果 | 落盘结构化结果、计算汇总、生成 MD、更新历史 | 留存中间文件，允许重试生成报告 |

任务生命周期为：草稿 → 准备中 → 安装中 → 执行中 → 整理结果 → 已结束。取消和异常中断也必须尽力经过“整理结果”；生命周期与测试结论分开保存。

### 4.2 超时与等待

以下为首版建议默认值，可在产品评审后调整：

| 项目 | 默认值 |
| --- | --- |
| 普通控件查找与断言 | 10 秒 |
| 启动或重启到可操作状态 | 30 秒 |
| 安装 APK | 120 秒 |
| 日志出现断言 | 10 秒；可在找到匹配后完成 |
| 日志不出现断言 | 5 秒；必须观察完整时间窗 |
| 单条用例 | 180 秒；可显式扩至 600 秒 |
| 整个任务 | 30 分钟；到期停止并输出部分结果 |
| 主动停止后的收集 | 最长 15 秒，超时记录未完成的证据 |

优先按元素或日志条件等待。点击成功仅表示动作执行成功，不表示业务成功；后面必须有可观测断言。条件轮询可以重复，提交动作不自动重复。测试执行器自身没有响应与 App 业务超时分开分类。

### 4.3 状态隔离

APK 每次任务安装一次。用例默认重启目标 App，保留应用数据；每例自己完成必要导航和前置检查。首版不允许用例隐式依赖上一条用例的成功状态。

用例可以声明需清数据，任务开始前汇总这些操作，并校验是否与登录前置条件冲突。清数据不能重置服务端账号、奖励次数或订单；涉及这些状态的用例必须准备专用账号或数据，并明确验证范围。

优先编写可重复设置状态的收尾步骤，例如将语言恢复为明确的初始语言。正常完成或断言失败后允许有界收尾；用户停止、断线、未知包切换、执行器异常时不继续发出收尾动作，记录“未恢复状态”。

配置了收尾步骤时，完成收尾也是用例的必需条件。主体已经失败时保留失败；主体断言满足但收尾失败时记为阻塞，并单独保留“主体断言满足”的事实。下一例只有重新准备并验证起始状态后才能继续；无法建立起始状态时停止任务，后续记未执行。

首版要求每个用例自包含，复用流程编辑器留到后续。验证码或人工登录在任务开始前完成；运行中遇到它们则按预设条件归为阻塞，不无限等待人工处理。

### 4.4 中断与恢复

设备断线后终止任务，当前例记阻塞，后续例记未执行；重新连接只能创建新运行，不接着点击旧步骤。设备重新上线也必须重新核对序列号、包和版本。

正常关闭客户端时显示正在执行的任务，提供“返回任务”和“停止并退出”。异常退出后，下次启动读取已保存的步骤事件，将未结束的运行标记为异常中断：已确认通过或失败的用例保持原结果，未得出结论的当前例记阻塞，尚未开始的例记未执行。生成可恢复的部分报告，不自动重新安装或继续操作设备。

取消安装只能停止本地等待或子进程，设备端安装可能已完成；报告必须写明安装最终状态已确认或未知。被测 App、账号和设备设置不承诺自动恢复到测试前状态。

## 5 结果判定

### 5.1 用例结果

| 状态 | 判定条件 |
| --- | --- |
| 通过 passed | 所有必需断言满足，必需观察窗口与证据完整，且无已归因目标应用的致命事件 |
| 失败 failed | 断言明确不满足，或确认属于目标应用的崩溃或 ANR；不自动认定具体代码根因 |
| 阻塞 blocked | 前置条件、设备、执行器或必需证据缺失，无法得出有效判断 |
| 已取消 cancelled | 用户主动停止时正在执行的用例，且之前尚无明确失败 |
| 未执行 not_run | 本次选择但未开始的用例，记录停止原因 |

步骤除这些终态外，可以显示等待中和执行中。已完成失败不会因之后断线、取消或截图失败而改成阻塞；原失败与后续故障都保留。若断言满足但必需证据丢失，不能直接给出通过。

找不到控件或文字不匹配，可确定“断言不满足”，但原因可能是产品变化、用例过期或环境影响；因此错误分类与根因判断分开。普通 Error 日志仅归为异常线索，除非它满足用例明确配置的失败条件。

### 5.2 任务汇总与计数

所有统计以本次选中的用例为分母，未选择的用例不混入统计：

- 选中数 N = 通过 P + 失败 F + 阻塞 B + 已取消 C + 未执行 U。
- 断言完成率 = (P + F) / N。阻塞或取消不算完成有效验收。
- 通过比例 = P / N，同时展示分子与分母；不以“已执行的成功项”为分母美化结果。
- N 为 0 时禁止开始；历史损坏导致 N 不明时显示无法计算，不展示 100%。
- 有失败时结论为“发现失败”；同时存在 B、C、U 时附加“本次验收未完成”。
- 没有失败但存在 B、C、U 时结论为“未完成验收”。
- 全部通过且必需证据完整时结论为“所选用例通过”。

每次重跑是独立运行。第一次失败后第二次通过，两次记录都保留；首版不把它们合并成一次稳定通过，也不计算没有足够样本支持的稳定性指标。

## 6 日志与证据

### 6.1 独立采集

测试日志直接增量写入结果目录，不依赖当前日志页的过滤、暂停显示、清空或内存保留策略。用户在日志页清空视图不会删除测试证据；执行测试不会调用全局 logcat 清空或终止共享 ADB server。

现有应用 UID 采集可以复用，但只按 UID 过滤可能遗漏由系统进程输出的目标 App 崩溃与 ANR 事件。需要补充相关 system、crash、events 事件采集，并结合包名、PID、UID 和时间窗归因。共享 UID、原生崩溃和厂商日志限制必须单独验收；不能把整机异常全部算给目标 App。

只有系统提供并成功读取的事件才能纳入结论。界面无响应而没有可靠 ANR 证据时，记录为页面等待超时或疑似卡住，不直接宣称系统 ANR。Release 包移除日志后，不能靠 AI 恢复日志；依赖该日志的用例应调整或标为不适用。

### 6.2 时间与关联

每次运行、用例和步骤均有固定 ID。事件同时保存主机时间、设备原始时间、单调时钟耗时及日志接收序号。开始和结束时记录设备与主机时间差；运行中时钟跳变或日志延迟进入证据质量说明。

日志断言使用明确的步骤时间窗与采集游标，不搜索设备中残留的旧日志。窗口只能减少误关联；重要业务事件优先匹配 App 输出的 requestId 或 flowId。没有关联标识时，报告注明基于时间窗关联。

日志流中断、丢行或窗口无法校准时，“未找到错误”不能判定为日志不出现断言通过。先保存原始分段记录，再生成可读合并版本与索引，保留二者对应关系。

### 6.3 截图与录屏

必需截图包括用例显式要求的检查点；失败截图尽力保存，失败事实不因截图失败被覆盖。截图文件记录设备、用例、步骤、抓取时间和成功状态。安全窗口黑屏或抓取失败应如实标注。

复用现有录屏能力时，一段录屏最长 180 秒。首版可按用例录制，但超过限制的用例只能说明“录屏覆盖前 180 秒”，不能写成全程录屏。录屏为可选证据；要提供更长的自动分段录像，需后续扩展并实机验证。

### 6.4 保存与导出

自动测试使用独立、可配置且跨启动记住的结果目录。运行开始前检查目录可写与剩余空间；建议低于 1 GiB 时阻止启用录屏，低于 256 MiB 时阻止开始。运行期间持续检查，无法继续保存必需证据时停止，不静默丢弃。

应用配置目录额外保留最小任务索引和状态日志，用于结果磁盘离线时解释中断原因。关键状态在步骤边界持久化，最终结果以临时文件写完后原子替换。目标结果目录不可写时，不安装或操作设备；运行中目录失效时，只保留能够成功落盘的证据并标明缺口。主机所有存储均不可写时不承诺完整恢复。

结果目录建议结构如下，首版产品运行数据不放入仓库或分发包：

~~~text
用户选择的测试结果目录/
  20261013-200000-随机标识/
    manifest.json
    result.json
    events.jsonl
    report.md
    input/
      app.apk
      suite.snapshot.json
      config.redacted.json
    evidence/
      app.log
      system-events.log
      runner.log
      cases/
        SETTINGS-001/
          steps.json
          failure.png
          step-log.txt
          recording.mp4
~~~

这些名称是未来数据格式的设计，不是本轮生成的测试产物。文件存在状态以 manifest 为准，不能为缺失截图生成看似可点击的链接。APK 快照用于重跑，默认不随报告导出；用户可以单独清理快照。

导出默认生成一个文件夹，包含 report.md、脱敏结果与相关证据；相对链接在整个文件夹移动后仍可用。不提供“只有 MD 却让本地附件链接失效”的默认导出。仅文本导出为额外选项，必须注明不含附件。

凭据引用保存在系统凭据存储，运行快照只存引用名；普通变量仍可能含敏感信息，需要提供敏感标记。日志与截图可能包含账号或业务内容：导出前可预览文本脱敏与选择附件，截图不能宣称已自动完全脱敏。首版不自动上传、发送或共享结果。

## 7 实现结构与依赖选择

### 7.1 现有能力与新增模块

| 模块 | 职责 |
| --- | --- |
| 现有 ADB 封装 | 设备查询与命令进程管理；为安装等长操作设置独立超时 |
| 现有日志核心 | 解析、分段合并、筛选与格式化；为测试增加持久证据索引 |
| 现有截图录屏 | 绑定固定设备保存画面；适配测试目录与步骤元数据 |
| 应用与用例仓库 | 应用配置、用例修订、导入校验和快照 |
| 测试编排器 | 生命周期、设备独占、超时、停止、状态保存和恢复 |
| UI 执行适配器 | 将受支持的动作转换为执行引擎调用，返回实际结果 |
| 断言与异常分析 | 检查 UI、日志和可归因系统事件，标明判断依据 |
| 结果与报告模块 | 统一结构化结果，驱动界面和 Markdown |

Mac 界面继续使用 SwiftUI 与 AppKit。用例和结果采用有 schemaVersion 的 JSON；Windows 可实现对应模型和执行适配器，不需要共享 Swift 二进制。跨端格式兼容不代表 Windows 实机已经通过验收。

### 7.2 Maestro 作为首选候选

优先验证本机 Maestro CLI。其官方文档说明可通过系统可访问性与输入接口进行黑盒操作；CLI 可指定设备、执行流程并生成 JUnit 或 HTML 结果。Logcat Mini 的 MD 和证据关联由本项目生成，不能将 JUnit 退出结果当作完整业务证据。[工作原理](https://docs.maestro.dev/get-started/how-maestro-works)、[CLI 参数](https://docs.maestro.dev/maestro-cli/maestro-cli-commands-and-options.md)

Maestro 官方当前列出 Java 17 及以上依赖。首版要把这些安装与诊断成本纳入首次配置；“普通日志能用”不能证明自动测试组件可用。[安装要求](https://docs.maestro.dev/maestro-cli/how-to-install-maestro-cli.md)

执行引擎还会使用设备端测试驱动。首次准备页面应说明驱动的用途、来源与版本，并将它和被测 APK 分开展示；不能把当前只读取应用名称图标的 Android helper 当成 UI 自动化驱动。驱动是否可以在测试后保留由组件管理策略明确记录。[设备端驱动说明](https://docs.maestro.dev/get-started/how-maestro-works)

APK 元数据解析还需要可靠的二进制 Manifest 读取能力。首版优先验证 Android SDK 的 aapt2 等工具适配，并在依赖检查中明确配置；不能简单从 APK 文件名推断包名、版本或启动入口。aapt2 来自 Android SDK Build Tools，与 platform-tools 中的 ADB 是不同组件。[AAPT2 官方说明](https://developer.android.com/tools/aapt2)

独立 APK 安装使用 ADB；不从设备自动提取用户其他 App 的安装包。首版只支持设备的主用户安装场景，工作资料、应用分身和多用户安装留到后续，预检发现这些目标时明确阻塞。

本项目的 JSON 用例不是 Maestro 原生 YAML。通过适配器编译受支持子集，不允许导入任意引擎脚本、任意 shell、外部脚本引用或无限循环。普通 QA 只使用表单，不接触执行器参数。

连续 UI 动作尽量编译为同一执行段；本地日志断言或主机侧检查点前后分段。段间不隐式重启或清数据，并记录精确边界。避免每个点击都启动一个全新执行器造成明显延迟。

### 7.3 编码前必须验证的技术门槛

正式实现前用目标 APK 与真机做一个窄范围验证，之后锁定经过验证的引擎版本：

1. 同一指定设备完成安装、启动、ID 定位、中文输入、等待、截图与退出。
2. 验证控件树读取、重复匹配检测、文本及可见性判断；不支持的控件类型应明确失败。
3. 验证执行结果文件的字段、失败步骤与附件对应方式，不能依赖终端彩色输出猜测通过。
4. 验证是否有可靠的实时步骤事件。若没有，首版按执行段更新，段落完成后显示步骤明细；不能承诺实时逐步进度。
5. 验证 UI 段与本地日志断言之间保持 App 状态，日志窗口不会命中旧记录。
6. 验证取消、断线、重启和异常退出后进程回收，不影响其他 ADB 工具。
7. 验证组件本地执行时的网络行为与可关闭的诊断上传设置，再确定隐私说明；不能因未使用云测试便宣称第三方组件绝不联网。

任一关键能力失败，应收窄首版支持动作或评估其他执行适配器，例如 UI Automator；不能在未验证时把兼容性写成已支持。Android 官方说明 UI Automator 可在应用进程之外测试，包括经过压缩混淆的发布版本，但仍需为测试准备执行设施。[Android UI Automator](https://developer.android.com/training/testing/other-components/ui-automator)

## 8 DeepSeek 后续接入

首版保存需求文字、实际步骤、预期与实际值、脱敏日志和证据引用，后续可用于模型输入，不需要改变测试结果的基本格式。

后续第一步建议做“分析本次失败”，第二步做“根据需求生成用例草稿”，最后再研究自主探索。模型输出需单独保存为分析记录，注明模型、时间、输入证据、建议与待确认事项，不直接改写既有通过或失败结果。

DeepSeek 官方提供工具调用接口；模型提出工具请求，实际执行仍由客户端负责。后续如加入操作能力，只开放受控的读取与测试动作，并有步数、时限和费用上限。[DeepSeek 工具调用](https://api-docs.deepseek.com/guides/tool_calls/)

本方案不固定后续模型名称或价格。接入时重新验证可用模型、图像能力、接口版本和成本；首版无 API 费用，也不自动将日志发给模型。

## 10 第一版验收清单

| 编号 | 验收场景 | 应观察到的结果 |
| --- | --- | --- |
| A01 | 导入正确 APK 与错误格式文件 | 正确读取元数据；错误文件明确拒绝，不猜测包名 |
| A02 | 两台设备连接，只选择其中一台 | 安装、动作、截图、日志均属于选择的序列号 |
| A03 | 签名不匹配、版本冲突、设备空间不足 | 记录安装失败，不卸载旧 App，不进入业务步骤 |
| A04 | 运行时修改或删除原始 APK | 本次使用已冻结快照；校验值与实际安装输入一致 |
| A05 | 运行中编辑用例并保存新修订 | 本次不变，下次可用新修订，历史能还原原版本 |
| A06 | 正常与错误 UI 预期各一条 | 分别通过和失败，报告列出实际值或未匹配原因 |
| A07 | 同一文字出现多次、中文输入、软键盘遮挡 | 不盲点第一个；输入和定位结果可验证，失败有明确步骤 |
| A08 | 前次已有匹配日志，本次未产生 | 本次日志断言失败或阻塞，不能命中旧日志通过 |
| A09 | 普通 Error、目标崩溃、其他 App 崩溃、ANR | 线索、目标故障和无关系统事件正确区分 |
| A10 | 点击提交后响应慢 | 有界等待；不自动重复点击或重试整条业务流程 |
| A11 | 设备断线、执行器异常、人工停止 | 保留完成结果，未执行项不变成通过，不切换设备 |
| A12 | 日志中断、截图失败、录屏超过 180 秒 | 报告明确证据缺口或录屏范围，必需观察缺失不通过 |
| A13 | 保存目录删除、权限变化、磁盘接近满 | 执行前阻塞或运行中停止；原始已存证据仍可找回 |
| A14 | 关闭并重启应用，或异常退出后重启 | 目录偏好、用例、历史恢复；未结束运行标为中断 |
| A15 | 导出到带中文或空格的路径，再移动文件夹 | MD 中附件链接可用，凭据不进入文本报告 |
| A16 | 首次失败后手动重跑通过 | 两个 runId 各自保留，来源关系明确，原失败不被覆盖 |
| A17 | 日志页清空、暂停显示、切换设备 | 不影响测试证据及测试目标，普通日志功能仍可使用 |
| A18 | 未配置 AI 或外部模型不可用 | 首版所有固定用例、结果查看和 MD 导出正常工作 |

需要保存以上验收的设备、APK 校验值和证据。Mac 自动化验收不替代 Windows 主机、USB 驱动、进程管理、路径与实机操作验收。
